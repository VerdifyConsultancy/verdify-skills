# Evidence review

Evidence is credible when it identifies source/command, timestamp, environment, revision, result, artifact location, and limitations. Confirm that CI and tests apply to the implementation head, that the later evidence head adds only the closeout, and that the report head adds only the critic report.

Reject narrative-only proof, screenshots without revision/environment, copied logs with no provenance, skipped required tests, and acceptance mappings that merely restate criteria.

Use independent spot checks where failure impact is high.
