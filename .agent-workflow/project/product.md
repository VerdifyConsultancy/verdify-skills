# Verdify Skills Product Definition

This human view is generated from the approved canonical YAML and does not add scope.

## Product Outcome

Verdify Skills is the internal-first lifecycle and agent-method layer that converts incomplete human intent and distributed evidence into approved, executable, independently reviewed, releasable, and verifiable work across Verdify Skills, Agent Platform, Orbit, and Gravity.

## Primary Users

- Jason: locks product intent, delegates bounded execution, and reviews evidence-backed outcomes.
- James: reviews exact heads and trusted package releases with explicit authority.
- Repository controllers: resume from durable state and coordinate one next lifecycle action.
- Lane workers and critics: execute or assess immutable scope with isolated authority.
- Internal and consulting consumers: install or vendor a versioned method package for a customer-scoped repository.

## Jobs To Be Done

- Convert transcripts, research, reviews, and live state into durable planning evidence.
- Lock intent, define the project end to end, and route the earliest incomplete lifecycle stage.
- Convert GitHub backlog into contracts, worktrees, sessions, PRs, and independent review.
- Publish exact package artifacts, verify deployments separately, and capture outcome acceptance.
- Coordinate runtime, governed context, and cited evidence through owned cross-project interfaces.
- Recover interrupted or unpublished work without losing knowledge or regressing accepted state.

## Scope

- Lifecycle and standalone skills, references, assets, trigger rules, and evaluations.
- CLI routing, validation, evidence ingestion, sprint/lane coordination, leases, prompts, and compliance.
- Canonical schemas and `.agent-workflow` planning/delivery artifacts.
- GitHub-native backlog, delivery, review, release, deployment, and reconciliation conventions.
- Package build, install, vendoring, provenance, release, rollback, and recovery contracts.
- Four-project ownership and interfaces for Skills, Agent Platform, Orbit, and Gravity.
- Internal-first use with later consulting reuse under the same authority model.

## Non-Goals

- Owning Agent Platform runtime, Orbit connector, or Gravity evidence-service implementation here.
- Replacing GitHub, npm, target GitOps, or project data stores without an approved migration.
- Preserving deprecated compatibility after an approved replacement.
- Granting unbounded product, production, credential, or approval authority to agents.
- Treating local tests, merge, or narrative confidence as deployment or outcome proof.

## Success Measures

- Repository, manifest, test, packed-install, skill, and schema integrity agree.
- Every validated state produces one earliest next route.
- Every integrated implementation has complete issue-to-review traceability.
- Every package release maps one tested artifact to one source, integrity record, provenance, tag, release, and ledger.
- Interrupted controller and release transactions recover without duplicates or lost work.
- Exact-head review evidence is current, nonempty, identity-valid, and resolved.
- Cross-project exchanges use versioned owned interfaces and readiness evidence.
- Every divergent work ref has a checked-in disposition and accepted content is present on `main`.

## Product Risks

The primary risks are ceremonial artifacts, reviewer deadlock, duplicate release generation, cross-project scope drift, governed-context privacy failures, and wholesale replay of obsolete recovery trees.
