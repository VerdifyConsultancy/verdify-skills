## PRODUCT-001 Purpose And Outcome

- Product purpose: Verdify Skills is the internal-first shared agent and method layer that binds planning, contracts, lifecycle execution, review, evidence, release verification, and platform adapters into one self-building software-and-knowledge platform.
- Primary declared customer: the integrated four-project pilot. Verdify Skills, Agent Platform, Orbit, and Gravity are co-equal active projects with their own product intent, GitHub backlog, deployment, and outcome acceptance. The root planning agent is the portfolio outer loop that reconciles priorities and dependencies; it does not replace each project's authority.
- Current state: the package has 26 shipped skills and a provenance-backed `1.2.1` release, but the July 9 review verified unsafe installer behavior, incomplete artifact and transition enforcement, disabled-operation dispatch assumptions, inconsistent North Star records, version drift, and separate project conventions. Agents, Orbit, and Gravity remain active but are not yet operating as one trusted loop.
- Target state: one issue can move through evidence intake, North Star planning, project-owned backlog, capability-negotiated dispatch, bounded implementation, fresh criticism, CI/CD, deployed verification, Gravity evidence retrieval, Orbit context/reporting, and outcome acceptance with every state reconstructable from GitHub and durable artifacts. The four projects can then use the same platform to build the next increment of the platform itself and onboard customer consulting projects through the same governed method.
- Distribution: Verdify Skills is primarily an internal capability. Public source or reference publication may occur later, but external community growth and a public compatibility promise are not current product goals.
- Compatibility: no backward-compatibility obligation is assumed. Deprecated or redundant capabilities should be removed after an atomic consumer convergence rather than carried as indefinite aliases or shims.
- Non-goals: do not build an external community, preserve deprecated behavior for its own sake, grant broad production mutation rights, replace GitHub as delivery control plane, or infer a future North Star lock from ordinary review or release activity.
- Success measures: all four pilots expose current lifecycle, capability, gate, runtime, evidence, and outcome state; one integrated vertical slice closes end to end; trusted package and transition gates are enforced; the system can select and complete its next bounded improvement without private chat state; a customer consulting repository can be onboarded without inventing a second lifecycle.
- Evidence: all registered evidence items, especially the July 9 adversarial review, Jason feedback, explicit iteration-25 lock approval, and fresh Agent Platform, Orbit, and Gravity audits (`northstar://evidence/NSE-20260709-*`), supported by the earlier delivery, security, GitOps, observability, session-ledger, control-request, backlog-sync, and learning-loop research.
- Architecture links: `ARCH-001`, `ARCH-004`, `ARCH-009`, `ARCH-021`.

## PRODUCT-003 PRD Summary

- Problem: the four active projects have useful but drifting lifecycle, runtime, information, and evidence capabilities. Without one outer planning loop, shared contracts, safe package distribution, and versioned integration interfaces, each project can advance while the platform as a whole remains unable to build itself reliably.
- Users: Jason, James, the root planning agent, pilot project owners, Orbit, worktree agents, reviewers, controller agents, platform operators, and Gravity evidence consumers.
- Jobs to be done: ingest evidence, maintain four project North Stars and backlogs, negotiate platform capabilities, execute bounded lanes, prove runtime deployment, retrieve cited Gravity evidence, turn authorized personal and enterprise context into Orbit workflows, and continuously select the next highest-value platform improvement.
- Minimum useful scope: research ingest, transcript replan, North Star artifact loop, repo hygiene, controller-loop specification, platform readiness, Gravity readiness, state-of-union, sprint planning, lane execution, critic review, and release verification.
- Differentiators: explicit North Star governance, a root-planner portfolio loop, common pilot and capability contracts, thin optional conversational adapters, repo-controller bootstrap/self-discovery, CI/CD wave lifecycle, review inbox, session ledger, proposal-only learning capture, loop-readiness checks, fleet observability and recovery, governed Orbit information workflows, current Gravity evidence interfaces, trusted package transactions, and traceable human-governed autonomous delivery.
- Out of scope: uncontrolled production autonomy, indefinite deprecated compatibility, a public community program, and treating an optional OpenClaw or Hermes implementation as the source of platform authority.
- Dependencies: GitHub, repo-local instructions, `.agent-workflow` artifacts, CI/CD checks, GitOps environment reconciliation, observability, and credentials/RBAC boundaries.
- Planning loop: distill evidence, propose research, answer questions where evidence supports an answer, propose design, accept human feedback, return to the loop, and request final lock approval only when the North Star is ready to advance to the next milestone.
- Owned-IP bias: own the root-planning method, lifecycle/evidence contracts, capability adapters, Orbit information workflows, and Gravity evidence interfaces while composing commodity Git, Kubernetes, GitOps, identity, database, connector, vector, and observability primitives.
- Evidence: all registered evidence items.
